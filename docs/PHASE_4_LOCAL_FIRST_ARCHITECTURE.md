# Phase 4 Local-First Architecture & Progress Persistence

## Overview
OVERLOAD operates on a permanent **Local-First** model tailored for instant, seamless mobile cognitive training:
```
OPEN APP → ONBOARDING → HOME → PLAY → RESULTS → PROGRESS
```
All login requirements, registration walls, and cloud authentication dependencies have been completely removed.

---

## 1. Zero Authentication Overhead
- **Non-Blocking Startup**: The application launches directly into [`SplashScreen`](file:///d:/BCA/Project/fullStack/brain-gym-app/src/screens/SplashScreen.js) → [`OnboardingScreen`](file:///d:/BCA/Project/fullStack/brain-gym-app/src/screens/OnboardingScreen.js) → [`HomeScreen`](file:///d:/BCA/Project/fullStack/brain-gym-app/src/screens/HomeScreen.js) without waiting for network authentication.
- **Immediate Readiness**: The app initializes local state in milliseconds from `AsyncStorage`.
- **100% Offline**: Zero network requests required for any gameplay, saving, or progress tracking.

---

## 2. Local Player Architecture & `localPlayerId`
- **Persistent Player Identity**: On first app launch, a persistent local player ID (e.g. `OP-8492`) is generated once and stored locally.
- **Player Profile**:
  - `displayName`: `"Operator"`
  - `operatorId`: Persistent `localPlayerId`
  - `accountStatus`: `"local"`
  - `storage`: `"Local Device (AsyncStorage)"`

---

## 3. AsyncStorage Structure & Centralized Storage Service
All local persistence is centralized in [`src/services/storageService.js`](file:///d:/BCA/Project/fullStack/brain-gym-app/src/services/storageService.js):

| Storage Key | Type | Description |
|---|---|---|
| `@overload/player_id` | `string` | Unique persistent local operator ID (`OP-XXXX`) |
| `@overload/player_profile` | `Object` | Player display name and identity metadata |
| `@overload/game_sessions` | `Array<Object>` | Complete historical array of completed drill sessions `[session1, session2, ...]` |
| `@overload/player_stats` | `Object` | Aggregated metrics (`totalDrills`, `currentStreak`, `cognitiveIndex`, `readiness`, `accuracy`, `latency`) |
| `@overload/faculties` | `Object` | Per-faculty level and telemetry map (`memory`, `focus`, etc.) |
| `@overload/settings` | `Object` | Player preferences (`haptics`, `sound`, `difficulty`, `notifications`) |

## 5. Analytics & Dashboard Calculations
All metrics displayed on Home, Training, Progress, and Profile screens are dynamically derived from actual stored local sessions:

1. **Total Drills**: `sessions.length` (0 if no games played).
2. **Mean Accuracy**: `Math.round(sum(accuracy) / sessions.length)` (`"—"` if 0 games).
3. **Mean Latency**: `Math.round(sum(latency) / sessions.length)` (`"—"` if 0 games).
4. **Active Streak**: Computed with calendar-day logic via [`streakCalculator.js`](file:///d:/BCA/Project/fullStack/brain-gym-app/src/utils/performance/streakCalculator.js) based on session completion dates.
5. **Cognitive Index**: Deterministic composite formula in [`cognitiveIndex.js`](file:///d:/BCA/Project/fullStack/brain-gym-app/src/utils/performance/cognitiveIndex.js) combining accuracy, response latency, peak memory span, and session experience.
6. **Cognitive Readiness**: Dynamic daily readiness score derived from recent drill precision and streak continuity.
